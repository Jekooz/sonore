4. WHAT THE POPULAR RAIL IS FED FROM (and why it can be absent)
====================================================================
The sidecar exposes no charts endpoint. The rail is therefore built from the feed
the page already loaded: every playable row, de-duplicated by track id, in
service order — real tracks, and hidden rather than invented when there are none.
The recorded fixture does carry song rows, so the desktop goldens show the rail.

====================================================================
5. THE FOLLOW CAPABILITY (new, real)
====================================================================
Backend: POST /library/subscriptions {artistId, subscribed} -> ytmusicapi
subscribe_artist(channelId) / unsubscribe_artists([channelId]); verified against
the installed ytmusicapi 1.12.3 (subscribe_artists is deprecated upstream, so it
is deliberately not used). GET /library/subscriptions was already present.
App: the hero's Follow button reads the real subscribed set, writes through the
sidecar, and re-reads; a failed write leaves the button showing what is actually
true and prints the service's own sentence instead of a fake success.
