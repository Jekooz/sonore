# Phase 2 — foundation and primitives: evidence and differences

Scope (chosen by the human): the spec's Phase 2 — `lib/theme/tokens.dart`,
typography, spacing, radii, `GlassSurface`, buttons, sliders, artwork tiles and
track rows, with widget tests for their states.

Standard used: the spec's "Done means", with the human's decision that goldens
are produced here and real device runs are listed explicitly.

`check_tokens.sh` enforces: hex colors, `Color()`/`Color.fromRGBO()`, `Colors.`
(except `Colors.transparent` in `GlassSurface`), numeric `fontSize`,
`TextStyle(`, `BorderRadius.circular(` and `\bIcons\.` outside `lib/theme/`,
plus `BackdropFilter` outside `GlassSurface`. It is a bash port of the repo's
`tool/check_tokens.ps1` so the two cannot drift.

## 2. What was built

```
lib/
  core/app_settings.dart     Riverpod 3 Notifier for reduce-transparency / reduce-motion
  theme/
    tokens.dart              the single source: color, type, shape, spacing, icons, layout, glass, motion
    app_theme.dart           ThemeData built only from tokens; token color scheme; NoSplash
    icons.dart               the one icon set (Phosphor regular + filled), codepoints centralised
  ui/
    glass_surface.dart       the only BackdropFilter; edge blur + 1.8x saturation + border + specular
    pressable.dart           press scale 0.97 / 80 ms, spring release, 48x48 hit area
    pill_button.dart         accent only when active
    art_tile.dart            surface placeholder, cached fade-in, concentric shape
    track_row.dart           64px row, 48px art, accent title when playing, surfaceRaised press fill
    seek_bar.dart            played/buffered segments, 4→8px on hover/touch, drag preview, one committed seek
    specimen.dart            development catalogue (goldens + hand review)
assets/fonts/                Inter 400/500/600/700 + Phosphor Regular/Fill (MIT)
```

## 3. Differences from the spec (D-items)

- **D1 — `phosphor_flutter` is not a dependency.** The spec names
  `phosphor_flutter`. Its latest release (2.1.0, also its last) declares
  `class PhosphorIconData extends IconData`, and `IconData` is now a
  `final class` in Flutter 3.47.7, so the package **cannot compile** (verified:
  the compiler reported `The class 'IconData' can't be extended outside of its
  library because it's a final class`). Resolution: the real Phosphor fonts
  (Regular + Fill, MIT) are bundled in `assets/fonts/` and the icon codepoints
  are centralised in `lib/theme/icons.dart`. It is the same icon set the spec
  asks for, wired through our own theme layer instead of the broken package.
- **D2 — the goldens capture the design-system catalogue, not a product
  screen.** Phase 2 defines primitives; the adaptive shell is Phase 3 and the
  real screens are Phase 4, so there is no screen to screenshot yet. The
  catalogue is rendered at all four required configurations.
- **D3 — `main.dart` mounts the catalogue.** This is a development screen, not
  a shipped product screen; it renders component specimens and carries no
  service data. It is replaced by the adaptive shell in Phase 3.
- **D4 — the loading / empty / error / offline screenshots are not produced.**
  The spec defines those as *per-screen* states, and no screen exists yet. The
  primitives do cover their own degenerate state (`SeekBar` renders inert when
  the duration is unknown or seeking is disabled).
- **D5 — Reduce Motion is partially wired.** The press scale is skipped and
  image fade-in collapses to zero under `MediaQuery.disableAnimations`. The
  spec's "replace movement with a 150 ms fade" for page changes needs routing,
  which arrives with the shell in Phase 3.
- **D6 — `rPill` is `Tokens.shapePill` (`StadiumBorder`)** rather than a
  numeric radius, so no pill radius literal exists anywhere.
- **D7 — the `error` color-scheme role is neutral text,** because the spec says
  error states use no red and there is no error color in the token table.
- **D8 — context menus are not built.** `design.md`'s Phase 2 sentence mentions
  "context menus", but the pasted spec's `lib/ui/` list is exactly
  `GlassSurface, ArtTile, TrackRow, PillButton, SeekBar`, and the menu
  *contents* are specified as screen-level behaviour ("Song and collection
  context menus"). They are deferred to Phase 4, where the rows that host them
  exist. No menu is stubbed.
