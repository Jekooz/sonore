Scope: replace the design-system catalogue as the entry screen with the real
adaptive shell, add the persistent mini player, and build Now Playing as the
first product screen, plus the loading / empty / error / offline states.

Approved decisions carried in: D1 (centralised Phosphor icon layer, bundled
licensed fonts) and D8 (context menus deferred).

## 3. Inspection performed (and what it did not cover)

Programmatic inspection of all 16 goldens: none is blank; each has a plausible
content profile (unique color counts 104–2290; non-black coverage 1.6% for the
sparse offline message up to 96.4% for the ambient Now Playing wash).

A coarse luminance map of each frame was rendered and read for structure. This
found one real defect, which was fixed: the offline golden rendered **no action
button** because a label was passed without a callback, violating the spec's
"empty (one sentence and one action)". After the fix the frame contains 3074 px
of exact `surfaceRaised` (the Retry pill) and the offline state has
`accent_px=0`, confirming no red.

Not covered: I cannot see the images. Structural checks confirm layout and
non-blankness but **not** visual quality, color harmony or clipping by eye. The
four desktop 1.3x frames rendered without Flutter overflow errors, which is
mechanically checked, not visually.

## 4. Differences from the spec (P-items)

- **P1 — Home, Search and Library render their empty state.** Their repositories
  and content arrive in Phase 4, so these destinations show an honest empty state
  (one sentence plus one action) rather than placeholder lists or mock content.
  Their action is real navigation, not an inert button.
- **P2 — No audio engine is attached.** `PlaybackController` owns real,
  unit-tested queue semantics (next/previous/repeat/shuffle/seek/like, 20 tests)
  and exposes `reportProgress` as the engine hook, but nothing produces sound in
  this phase. In the shipped app the player is therefore empty and Now Playing
  renders its empty state; the populated layout is exercised by tests and goldens
  driving the production controller. design.md stages the engine at Phase 5.
- **P3 — Lyrics and EQ are not in the Now Playing action row.** Their screens
  are Phase 4, so the row carries Like and Queue, both of which work against real
  state. Nothing is rendered that cannot act.
- **P4 — No Hero between the mini player and Now Playing.** Now Playing is a
  shell branch with its own Navigator, so a Hero flight cannot originate from the
  shell-owned mini player. Navigation is a branch switch; tap and swipe-up both
  open Now Playing.
- **P5 — Spring motion is approximated with curves.** The carousel snap and the
  artwork play/pause scale use `Tokens.curveSpring` (`Curves.easeOutBack`) rather
  than a `SpringSimulation` of the spec's mass/stiffness/damping values.
- **P6 — Goldens render artwork as the designed no-artwork placeholder.** Tests
  must not fetch images, so `artworkResolverProvider` is overridden to null and
  the artwork-derived ambient wash is rendered from a fixed palette fixture.
  Inter and both Phosphor families are loaded, so text and icon glyphs are real.
- **P7 — The offline screenshot is a composed state.** No destination has a data
  layer yet, so no screen can legitimately be offline; the shot renders the shared
  state widget that Phase 4 screens will use. Loading, empty and error are the
  real Now Playing screen in each state.
- **P8 — `flutter test` was run with `--concurrency=1`.** The default parallel
  runner fails on this machine with `Error: Flutter failed to copy file ... The
  target device is full`, because **C: is 100% full with 402 MB free**. This is
  an environment limit, not a test failure: every file passes individually and
  the whole suite passes serially in ~13s.
- **P9 — The sidebar uses the flat `surface` token, not glass.** The shell
  paragraph calls it a "glass sidebar", but spec principle 3 reserves glass for
  floating chrome. The bottom bar *is* glass, as specified.
- **P10 — Now Playing keeps the navigation and hides the mini player.** It is one
  of the four destinations (with an active, accented nav icon), and the page is
  the player, so the mini player steps aside rather than duplicating transport.
