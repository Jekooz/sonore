5. DESIGN-DIFF AUDIT (section 2 of the brief)
====================================================================
5a. The light palette - files, selection path, verdict: INCOMPLETE / DEAD CODE
    Introduced in ytm_app/lib/theme/app_theme.dart: a `Palette` class with
    `Palette.dark` (wraps Tokens verbatim) and `Palette.light` (hand-written
    values), and `AppTheme.build(Palette)` with `AppTheme.dark` / `AppTheme.light`.
    It is NOT selected anywhere:
      - lib/app.dart:30-31 hard-codes `theme: AppTheme.dark, themeMode: ThemeMode.dark`
      - `grep -rnE "AppTheme|Palette|ThemeMode" lib test integration_test` outside
        app_theme.dart returns only: AppTheme.dark in app.dart and in
        specimen_golden_test.dart, primitives_test.dart, screen_states_test.dart.
        `AppTheme.light` has ZERO references outside its own file.
      - `AppSettings` (lib/core/app_settings.dart) has no theme field, so no
        provider, token or stored preference can select it.
      - the Settings screen states: "Theme: dark. This version ships one theme,
        so there is nothing to switch."
      - design.md:6 states the intended scope: "dark-only v1".
      - `AppTheme.light` is not even built at startup, so it cannot throw.
    Verdict: unreachable, unselectable code that contradicts the spec's stated
    v1 scope. It has no user-visible effect. Per the brief it was NOT reverted.

5b. sidebarWidth 220 -> 200: INTENTIONAL and spec-correct.
    Evidence: design.md "Desktop measurements" -> "| Sidebar | 200 px base width;
    16 px internal padding |". Consumed by lib/features/shell/nav_rail.dart:44
    (`expanded ? Tokens.sidebarWidth : Tokens.sidebarRailWidth`).
    The only thing wrong was the docstring beside it, which still quoted 220 -> corrected (2a).

5c. titleBarHeight 40 -> 36: INTENTIONAL; no contradicting evidence.
    Consumed by lib/features/shell/window_title_bar.dart:33 and :81.
    design.md states no title-bar number (only "respect OS caption controls");
    the token's own comment cites the Figma frames drawing a 36 px bar with a
    46x36 caption hit area, and Tokens.captionButtonWidth is 46. Nothing in the
    repo asserts 40.

5d. Colour values: BACKED BY THE FIGMA EXPORT, BUT BOTH WRITTEN DOCS ARE STALE.
    Changed in lib/theme/tokens.dart:
      glass          white 6%  -> white 8%   (0x0FFFFFFF -> 0x14FFFFFF)
      textSecondary  #A6A6A6   -> #A0A0A8
      textMuted      #7A7A7A   -> #686870
      glassFallback  -> #242427
    The written specs still list the OLD values:
      design.md:205-207   textSecondary #A6A6A6, textTertiary #7A7A7A, glass 6%
      DESIGN_TOKENS.md:19 --glass: rgba(255,255,255,0.06)
                          :24 --text-secondary #FFFFFF @55%
                          :25 --text-muted #FFFFFF @32%
    The working tree's claim is that these were re-extracted from the exported
    Figma spec (design.pdf) and that the old values came from the earlier mock
    draft. That claim was INDEPENDENTLY TESTED, not taken on trust. design.pdf's

    operators extracted:
      #A0A0A8 present 454x     #686870 present 64x     #242427 present 1x

    UNRESOLVED: the glass tint. The PDF exposes no `/ca` `/CA` alpha operators
