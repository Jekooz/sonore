2. STEP 1 AUDIT — CONFIRMED ARCHITECTURE (checked, not assumed)
====================================================================
- Sidecar: ytm_app/lib/core/sidecar/{sidecar_launcher,sidecar_io,sidecar_providers,
  sidecar_startup_gate}.dart. Injected spawner/port-file/probe/log/killer; real

  widget/golden test spawns a process.

  discovers via the port file then falls back to 127.0.0.1:8000 (and
  10.0.2.2:8000 on Android); a failed request drops the cached base URL and
  re-discovers once (covers restart-on-a-different-port).
- Auth: SignInController + /auth/browser/* and /auth/extension protocol;
  backend validates a candidate against YouTube BEFORE storing, so a bad
  hand-off cannot destroy a working session.
- Playback: ytm_app/lib/audio/{playback_engine,playback_service}.dart.
- Recorded-sidecar seam: unchanged (ytm_app/test/support/recorded_sidecar.dart).

8. REMAINING LIMITATIONS
====================================================================
- /stream resolution depends on yt-dlp and the network; if YouTube changes or
  the network is unavailable the test fails loudly rather than silently passing.
- The signed-in assertions ran against this machine's existing session; on a
  clean machine the same code takes the signed-out branch, which is also
  asserted, but has not been run on a clean machine here.
- Sign-out (POST /auth/signout) and ratings (POST /ratings) are mutating and
  were deliberately NOT called against the real account; they remain covered by
  the recorded-sidecar unit tests.
- The backend publish-port mechanism while already listening: with YTM_PORT
  pinned (8199/8201) and YTM_PORT_FILE isolated, an isolated instance never
  contends with a live app's port or file.
