  Lyrics and Equalizer are reached from Now Playing, matching design.md.

Shared layout / tokens / components
  lib/theme/tokens.dart (the only place values are defined), lib/theme/icons.dart,
  lib/ui/{screen_header,screen_states,data_states,pill_button,glass_surface,...},
  lib/features/shell/*, lib/features/now_playing/*. All three screens are built
  from these; tool/check_tokens.sh enforces it (below).

Is lyrics data exposed by the backend?  YES.
  backend/main.py:1040-1155 - GET /lyrics/{video_id}
    200 {videoId, available:true, synced, lines:[{text, startMs?, endMs?}], source}
    404 YouTube Music has no lyrics for this track (a real answer, not a failure)
    400 malformed video id
    401 not signed in (raised by _data() -> AuthError("Not signed in.")
        at services/ytmusic_client.py:367)
  Resolution is two real upstream calls: get_watch_playlist yields the track's
  lyrics browse id, then ytmusicapi get_lyrics resolves it. `synced` is true
  ONLY when the provider reports hasTimestamps is true; otherwise the untimed
  lookup is returned as plain text. The handler never invents timings.
  60-minute / 64-entry in-process cache; timed lookup runs on a throwaway
  anonymous client because the mobile endpoint rejects a logged-in context.
  App side: lib/data/ytm_repository.dart:249 lyrics() -> lib/data/api_client.dart
  ; model lib/data/models.dart:444 LyricsLine / :457 LyricsResult.

Does the audio engine support real equalizer processing?  YES, via libmpv.
  lib/audio/equalizer.dart - media_kit's Dart Player API exposes no audio
  filters, so the EQ writes mpv's own `af` property through the libmpv the app
  already links (media_kit's generated bindings + the live mpv_handle from
  Player.handle). The value is a real ffmpeg `equalizer` stage chain inside one
  `lavfi` graph (`buildMpvAudioFilter`), and every write is read back off the
  engine (`readFilter`) so "the control changed the processing configuration"
  is asserted rather than claimed. Bands: 10 (31, 62, 125, 250, 500, 1000,
  2000, 4000, 8000, 16000 Hz), each clamped to +/-12 dB. EqualizerEngine is an
  abstraction with `isSupported`; when there is no libmpv the app builds
  UnavailableEqualizer and the screen says so instead of showing dead sliders.
  Persistence: the shape is stored in the settings record and re-applied at
  startup (playback_service._applyPersistedEqualizer).

Existing settings / persistence / diagnostics
  lib/core/app_settings.dart - AppSettings (reduce transparency, reduce motion,
  text scale, lyrics auto-follow, equalizer shape, repeat mode, shuffle,
  autoplay) with validating fromJson/copyWith; AppSettingsNotifier writes every
  change through a SettingsStore and reports save status.
  lib/core/settings_persistence.dart - SharedPreferencesSettingsStore (raw reads,
  every value validated, corrupt value degrades to default).
  lib/main.dart loads the store before the first frame and overrides the
  provider, so the app opens on the stored preferences.
  Diagnostics: the Settings screen reports the live sidecar connection and the
  local-runtime state with a re-check action, and the account state with a
  sign-out behind a confirmation. It shows no cookie, token or signed URL.

States identified (and each is implemented and tested)
  loading (skeleton) | lyrics available (timed and untimed) | no lyrics |
  sidecar offline | request failure + retry | signed-out | nothing playing
  (Lyrics); engine supports EQ | engine cannot shape audio (Equalizer);
  saving | saved | save failed, and a reset confirmation (Settings).

3. FUNCTIONAL CAPABILITIES IMPLEMENTED PER SCREEN
====================================================================
Lyrics (lib/features/lyrics/lyrics_screen.dart, lyrics_controller.dart)
  - data comes only from /lyrics/{videoId}; nothing is scraped and no endpoint
    is invented. The controller refetches on track change so the previous
    song's words never sit over the next song.
  - synced lyrics: the line whose start time has passed is highlighted, the view
    scrolls to it, and each timed line is a real seek target (tapping seeks).
  - static lyrics: rendered as plain text; a line with no timestamp is NOT a
    seek target, because offering a time that does not exist would lie.
  - states: skeleton while loading; "No lyrics for this track." with a footnote
    when the service answers none; offline state; failure state with retry;
    sign-in state when 401; "Nothing is playing." when the queue is empty.
  - following stops when the reader drags by hand and offers "Back to current
    line"; the "Follow playback" preference is honoured.
  - accessibility: lines are Semantics(button, "Go to <line>"), the header back
    action is labelled, and reduce-motion turns the scroll into an instant jump.

Equalizer (lib/features/equalizer/equalizer_screen.dart,
lib/audio/equalizer_controller.dart, lib/audio/equalizer.dart)
  - every control writes into the running engine and the engine's own answer is
    shown back ("Engine reports" <af value>), so nothing on the screen is
    decorative.
  - on/off switch; five named presets that are actually applied; 10 band sliders
    with a dB readout and a frequency label; "Reset to flat"; an applying
    indicator; an error line when the engine refuses.
  - accessibility: each band is Semantics(container, "<freq> hertz band",
    value "<n> decibels"); the switch is Semantics(toggled).
  - if the engine cannot shape audio the screen renders the honest unavailable
    message and no controls.

Settings (lib/features/settings/settings_screen.dart)
  - Appearance: reduce transparency, reduce motion, text size (clamped to the
    supported range). A note states plainly that this version ships one theme.
  - Playback: autoplay, shuffle (both owned by PlaybackController, so the
    transport pill and this screen cannot disagree); repeat is noted as cycling
    from the transport.
  - Lyrics: follow playback.
  - Audio: equalizer summary + link to the Equalizer screen.
  - Diagnostics: live connection + local-runtime state with a re-check action.
  - Account: sign-in state and sign out behind a confirmation.
  - Privacy: states where the session lives; no cookie/token/signed URL is shown
    or logged.
  - About: version and licence note.
  - Footer: "Reset preferences" behind a confirmation dialog.
  - A save-status banner reports saving / saved / could-not-save, so a failed
    write is visible instead of silent.

7. THE ONE PRODUCTION-BEHAVIOUR DISCREPANCY FOUND, AND HOW IT WAS SETTLED
====================================================================
`flutter test integration_test/backend_api_test.dart -d windows` first ran
"+9 -1":

  test:    the real validator rejects an incomplete cookie hand-off without
           storing it
  failure: Expected: <422>   Actual: <409>

Cause, established from the code, not guessed. The working tree's backend had
added a security gate (documented at backend/main.py:187-215 as "Security fix
(audit finding 1)"): /auth/cookies now runs under the same pairing gate as
/auth/extension, so

  - no sign-in in progress          -> 409 before the validator is reached
  - bad/absent pairing token        -> 401
  - pending + valid token, bad jar  -> the validator's 422

The restored HEAD copy of the app-side integration test posted a bare cookie
hand-off and expected the validator's 422. Under the gate it never reaches the
validator, so 409 is correct and the 422 expectation was stale. The backend's
OWN tests were already updated for this by the same workstream and pass
(tests/test_auth_pairing.py: `test_incomplete_jar_is_rejected_before_storage`
drives a real handshake and still asserts 422; `test_legacy_cookies_endpoint_
is_gated_like_the_extension` asserts the gate).

The app-side test was corrected to assert what really happens, and strengthened
rather than loosened - it now requires the gate's own wording and that nothing
was stored:

  expect(response.statusCode, 409);
  expect(response.body, contains('No sign-in is in progress'));
  expect(response.body, isNot(contains(notARealCookie)));
  expect(await client.isSignedIn(), signedIn);   // session unchanged

Re-run: "00:37 +10: All tests passed!"  EXIT=0.
No application code was changed: the validator's 422 path is still reachable by
the app through /auth/extension (the flow the UI actually uses), and
api_client.dart still maps 422 -> signed-out for it.
